# middleware/ — 协作中间件

> 状态：占位骨架，M1 实现。若 Spike ② 确认 Cerebrum SDK 原生具备消息路由/工作流编排能力，则本层退化为薄封装；否则按以下设计自研。

在 OS 叙事下，本层即「多智能体操作系统」的核心：

| 组件 | OS 对应物 | 职责 |
|---|---|---|
| **MessageBus** | IPC | 发布/订阅消息路由；消息 `(msg_id, from, to, type, round, ts, payload)` 全量落盘，供回放与演示 |
| **DAGScheduler** | 进程调度器 | 按诊断计划 DAG「就绪即派发」并发调度子任务；完成事件驱动下游；实现赛题要求的先后顺序与依赖约束、按类型自动分配智能体 |
| **SharedWorkspace** | 文件系统 | 基于 AIOS Storage Manager 的共享工件区（采集片段/诊断单/根因结论/修复日志/报告），智能体间传引用不传大文件，控制 7B 上下文长度 |

调度模式开关（性能实验用）：`SERIAL`（按拓扑序逐个执行，同构基线）/ `CONCURRENT`（就绪即派发 + vLLM 批处理）。两种模式共用同一套智能体与提示词，仅调度不同——保证提速对比的公正性。
