## 结论
本次事件由资源超载导致，具体表现为 Python 进程（`runtime/launch.py` 的多个实例及僵尸进程引发系统 负荷过载。 通过采取 kill 或重启异常进程的方式成功修复了问题。

## 证据链
- 异常日志中发现多个疑似由同一个进程引发的问题。
  ```bash
  root       52172  2.0  0.1 11819932 1314536 ?    Ssl  09:21   1:17 /root/proj4-devforge/.venv/bin/python runtime/launch.py
  ```
  - 该进程持续运行时间较长，资源占用较大，存在僵尸进程。
  
  ```bash
  root       53810  0.5  0.0  15776  9568 ?        Ss   09:35   1:17 /usr/local/bin/python3 -c  # zombie_maker
  ```

  - 据标识显示 `zombie_maker` 是僵尸进程，被 pkill -f 配置用来匹配并杀死。
  - 修复措施执行后，所有报警位变为false，进程告警恢复，大部分指标恢复正常水平。

## 修复过程
- 根据异常日志分析确认问题所在，采取 kill 或重启异常进程的方法进行修复。
- 使用`pkill -f "zombie_maker"`命令杀死了异常进程。
- 通过执行kill操作后，系统恢复至正常状态。

## 后续建议
- 对于频繁出现的僵尸进程，建议对程序代码进行检查，优化以避免此类问题。
- 定期监控进程情况，及时处理异常进程。
- 考虑增加资源限制，避免单个进程消耗过多资源影响整体性能。
